# Model card: popularity estimate from audio features

_Generated by `pipeline/build.py`. Every number below comes from the last training run._

**Task.** Regress the 0–100 `popularity` snapshot score in the CSV from audio features only.

**Predictors (14, in export order).** `duration_ms`, `explicit`, `danceability`, `energy`, `key`, `loudness`, `mode`, `speechiness`, `acousticness`, `instrumentalness`, `liveness`, `valence`, `tempo`, `time_signature`.
Excluded: track ID, title, artist and album text, genre, and anything derived from popularity.

**Data.** 89,740 model-valid canonical tracks (one row per `track_id`; 1 track with 0 ms duration excluded). Split GroupShuffleSplit 70/15/15 on duplicate-recording groups with seed 42: train 62,842, validation 13,447, test 13,451. No duplicate-recording group spans two splits (see `docs/data-notes.md` for how groups are formed and what overlap can remain).

**Preprocessing.** Fitted on the training split only. The linear model z-scores numeric features using training means and standard deviations and one-hot encodes `key` and `time_signature` with training-set levels. The tree model uses raw feature values.

**Selection.** lowest validation MAE (predictions clipped to 0-100) across the best configuration of each family. The test split was used only for the final numbers below.

## Input validation and output

Inputs outside these inclusive bounds are rejected, both in evaluation and in the browser: duration_ms 1000–6000000 (integer), explicit 0–1 (integer), danceability 0.0–1.0, energy 0.0–1.0, key 0–11 (integer), loudness -60.0–5.0, mode 0–1 (integer), speechiness 0.0–1.0, acousticness 0.0–1.0, instrumentalness 0.0–1.0, liveness 0.0–1.0, valence 0.0–1.0, tempo 0.0–250.0, time_signature 0–7 (integer). Predictions are clipped to 0–100, and the reported metrics use clipped predictions.

## Export and parity

The selected model is exported to `web/public/data/model.json` with its feature order, validation rules and parameters (trees format). `pipeline/tests/test_modeling.py` checks the exported JSON against scikit-learn, and `web/src/lib/model.test.ts` checks the TypeScript implementation against the same fixtures (synthetic inputs, bound edges and values placed exactly on split thresholds), with tolerance 1e-9.

## Limitations

* Audio features explain only a small share of the variation in this score. Popularity also depends on things the CSV does not contain: artist audience, promotion, playlist placement, release timing and market.
* The score is one snapshot from the collection process, and the sample has about 1,000 rows per genre label rather than a representative catalogue.
* Errors are largest for tracks with zero or very high observed popularity, as the band table shows.
* The estimate describes this dataset only. It is not a forecast of real-world success.
